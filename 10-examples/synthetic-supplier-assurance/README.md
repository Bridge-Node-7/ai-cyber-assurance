## Scenario

A fictional AI-assisted workflow called **Synthetic Supplier Evidence Review S-17** reviews evidence submitted by a fictional supplier for **Sample Material M-17**.

The AI review agent:

- Reads only the approved synthetic evidence package.
- Compares declared record identifiers and hashes.
- Flags inconsistencies.
- Drafts a review summary.
- Cannot approve, reject, publish, modify source records, revoke access, or change supplier status.

A fictional human assurance reviewer retains authority to:

- Determine evidence sufficiency.
- Request corrective action.
- Approve or reject supplier status.
- Accept residual risk.
- Authorize release of an assurance statement.

## Demonstrated Journey

```text
Synthetic supplier onboarded

→ fictional hash mismatch detected
→ evidence gap documented
→ human reviewer imposes conditions

```

## Why the Decision Remains Amber

The synthetic discrepancy was corrected and rechecked, but the example does not include an executed recovery test for loss of the evidence service. The decision is therefore limited to a controlled fictional pilot.

## What This Example Proves

It demonstrates how the repository can connect AI assistance, supplier evidence, identity, integrity, controls, gaps, corrective action, and human authority.

It does not prove:

- Security
- Supplier qualification
- Material conformity
- Production readiness
- Compliance
- Certification
- Independent validation
- Real-world performance
